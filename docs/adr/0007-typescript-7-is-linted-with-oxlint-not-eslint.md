# The code stays on TypeScript 7 and is linted with Oxlint, not ESLint

This repository uses `typescript@7`, the native compiler, which ships no JavaScript compiler API; typescript-eslint and eslint-plugin-sonarjs need that API and crash on load, so the ESLint stack the user-level policy names cannot run here. The alternatives were to pin `typescript@~6.0` so that ESLint could run, or to keep TypeScript 7 and enforce the same policy through Oxlint with `oxlint-tsgolint` (its type-aware backend built on the native compiler) and `eslint-plugin-security` loaded as a JS plugin. The second was chosen: every size, complexity, type-escape-hatch, promise and security rule of the policy is an error in `oxlint.config.ts`, `bun run lint` (`oxlint --deny-warnings`) exits 1 on any finding, and it gates `deploy.yml`, `check.yml` and `update-data.yml`. What Oxlint cannot provide is accepted knowingly: sonarjs's cognitive complexity is replaced by cyclomatic `complexity` at 15 instead of 20, and its assertions-in-tests rule by the practice of seeing every new test fail first. An exception to a rule lives in `oxlint.config.ts` with its reason and removal condition, never as an inline disable comment. Do not add ESLint or pin TypeScript back to 6 to get it; re-examine this only if typescript-eslint gains TypeScript 7 support and something the Oxlint path lacks is needed.
