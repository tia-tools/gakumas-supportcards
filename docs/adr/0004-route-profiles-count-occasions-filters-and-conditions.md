# Route profiles count occasions, filters and conditions; the game's filter table only supplies names

A route profile used to hold one hand-entered count per row of the game's card-filter table (ADR 0002), which made 41 sibling numbers out of what are really three different things, forced a person to write numbers into every profile whenever the game added a row, and could not express a conditional effect honestly. Counting now follows the structure the trigger ids already have. An occasion is the game's own `ProduceTrigger.phaseType` (19 today: a lesson ends, a skill card is acquired, an audition ends); a filter says which occasions qualify and is a count bounded by its occasion, organised in families (card type, effect group, rarity, lesson stat) with one default per family so a new member needs no human; a condition is a state of the run that must hold (deck of 20 or more, a stat at 400 or more) and is a count bounded by its occasion that defaults to the maximum. A never-seen piece of a trigger id is classified by its shape (threshold-shaped means condition, a known slot means a new family member) and anything else hides its card and asks a person. The filter table `SupportCardProduceSkillFilter.yaml` is demoted to a source of in-game display names. Alternatives rejected: our own curated occasion list (a mapping decision for every new phase), keeping per-row counts and only regrouping the panel (updates stay manual, conditions stay free-standing numbers).

Source: user decisions C1–C4 and agent decision C5 in the grill-me session of 2026-09-21 (`docs/plans/EXECPLAN_COUNTING_MODEL.md` § Decision Log). Evidence: 81 parameter-bearing triggers across support skills and card-granted P-items reduce to 19 phase types, and every other id segment falls into a small vocabulary of filter slots and threshold-shaped conditions (same plan, § Surprises & Discoveries); the data update of 2026-09-20 needed three manual profile edits that this model makes unnecessary. Not yet implemented: until that plan's migration lands, the code still counts per filter-table row as ADR 0002 describes.
