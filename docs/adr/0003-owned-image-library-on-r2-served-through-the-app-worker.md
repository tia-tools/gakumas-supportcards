# Card thumbnails come from an owned image library in Cloudflare R2, served through the app's Worker

No public mirror of support card art exists (gk-img covers idols, P-items and skill cards only; hatsuboshi-library serves from its author's private Cloudinary account behind a URL scheme `img_general_{assetId}_full.webp`). We extract the art ourselves from the game CDN, downscale to webp, keep the game's filename convention, and store it in an R2 bucket bound to this app's Cloudflare Worker, which serves `/img/*` with immutable cache headers next to the static site. This keeps one subdomain per app (the tia-tools rule), costs nothing at this size, and lets future tia-tools apps reuse the bucket. Alternatives rejected: a git image repo on GitHub Pages (binary churn, would need a second subdomain or a github.io URL), bundling into the app's `public/` (image refresh becomes an app deploy, no reuse), our own Cloudinary account (vendor outside the stack), hotlinking someone else's mirror (their bandwidth, no permission). The URL prefix is a single constant in the app so the store can move later; the filenames cannot change cheaply once shared.

Source: user decision D6 after comparing four options, grill-me session 2026-09-16 (`docs/plans/EXECPLAN_SUPPORT_CARD_SCORE_TABLE.md` § Decision Log). hatsuboshi-library findings verified by reading its `app/assets/media.ts` and live bundle the same day.

Addendum 2026-09-21 (status unchanged, scope refined): the library stores two renditions per card instead of one downscaled webp. `master/img_general_{assetId}_full.webp` is the decoded texture as lossless webp at its own size and is private: the Worker's path rule matches only the thumbnail prefix, so a master is unreachable from the web. `w192/img_general_{assetId}_full.webp` is the 192 × 108 thumbnail and the only public image, served at `/img/w192/…`. The game's file name is kept in both; the rendition is a prefix, so a future size never renames anything. Reason: re-extraction cannot be relied on (the game can replace assets, and the extraction library's converter already broke on an engine change), all masters together are about 219 MB against a 10 GB free tier, and the naming had to be fixed before the first deployment shared it. Masters are kept private because storing is not publishing. Source: user decision D35, session 2026-09-21 (`docs/plans/EXECPLAN_SUPPORT_CARD_SCORE_TABLE.md` § Decision Log), sizes measured on the real extraction.
Further addendum 2026-09-21: the master is stored at the game's display shape, 2048 × 1152, not "at its own size" as the addendum above says. The game keeps card textures squashed to 2:1 and stretches them to 16:9 when showing a card; a master left at 2:1 looked wrong to the user on first sight and would be misused by any future reader that does not know the rule, so the one resample is accepted and the file is self-sufficient. 204 masters are 265 MB. Source: user decision D36, same session and plan.

Addendum 2026-09-29 (status unchanged, one more prefix): the library also holds the icons of the P-items cards grant, named by the game's own asset id `img_general_pitem_{r}-{nnn}.webp` (no `_full`): a lossless 256 × 256 master with its transparency under `master/`, with no reshape (the 16:9 rule is card-only), and a 48 × 48 webp with alpha under the new public prefix `w48/`, served at `/img/w48/*`; released-cards-only and master-first apply unchanged, and an icon goes out only with a released card that lists the item. One rule made explicit: `upload.py --rendition w192` and `--rendition w48` send the public rendition together with its master, because a master cannot be checked from outside (it is private) and a public-only run on a file the site lacks would otherwise publish it without one — a risk `--rendition w192` had carried since D35, found by a Codex review. Source: decisions A12 and A23 and finding F7, 2026-09-28/29, `docs/plans/EXECPLAN_SCORE_ADJUSTMENTS.md`; evidence: 49 icons uploaded on 2026-09-29, `HEAD /img/w48/img_general_pitem_2-004.webp` → 200 immutable, the planner reporting `253 already served, 0 missing`.

Addendum 2026-10-31 (status unchanged, two more prefixes and the first object that changes under its name): the library also holds what `tia-tools/gkms-memomemo` draws skill cards with. Under `w112/`, the icon of every skill card in `data/skillcards.generated.ts` (released, and able to be a produce memory), named as the game names the bundle: `img_general_skillcard_{kind}-{n}_{nnn}.webp`, or one per playable idol with `-{idol id}` where the card is drawn differently per idol; a 112 × 112 webp with transparency, with a lossless master as stored (256 × 256, no reshape) under `master/`. Under `sheet112/`, sprite sheets built from those masters, one per plan and playable idol (39), 10 columns of 112-pixel cells in the game's order, at WebP quality 80 with exact alpha (118–124 KB each), named `{plan}-{idol id}-{first 8 hex digits of the sheet's SHA-256}.webp` so a name never changes meaning, and `sheet112/index.v1.json`, which names every current sheet and its cells and is the one object the pipeline rewrites under the same name: it is stored and served with `Cache-Control: no-cache`, everything else immutable. A sheet is rebuilt only when the stored index lists other icons or another layout for it, never by comparing bytes. Uploads keep an order, an icon (master first) before any sheet holding it and the sheets before the index, which lets the planning treat an icon the stored index names as stored without a request; the index is checked entry by entry before it is trusted, and `sheets.py --rebuild` replaces a damaged one trusting nothing stored. Sheets the index stops naming stay in the bucket. Reason: on the Workers Free plan every `/img/*` request counts toward the account's daily allowance shared by every `tia.run` Worker, so the consumer loads three sheets rather than about two hundred single icons (its decision D42); this site serves `w112/` and `sheet112/` so that its own upload can ask what is stored. Source: issue #65 and `docs/plans/EXECPLAN_SKILLCARD_DATA_AND_ICONS.md`, decisions K9–K14, K18 and K19 (K19 from a Codex review). Evidence: 1,693 pool icons of 2,226 offered extracted from manifest `205100:0075`; 39 sheets measured at qualities 50–90, all under 182 KB; `uv run pytest` (62 tests) pins naming, staleness, the index check and the upload order.

Evidence after the first upload, 2026-10-31 (status unchanged; the addendum above now holds on the live site): after release #69 and the first bulk upload (`uv run upload.py`, then `uv run sheets.py`), `/img/sheet112/index.v1.json` answers 200 `application/json` with `no-cache` and lists 39 sheets, of 68, 68 and 65 icons per idol. Every sheet answers 200 `image/webp`, immutable, and the 8 hex digits in its name are the start of its SHA-256. All 1,693 icons it names answer 200 under `/img/w112/`, a `master/` path answers 404, and a second `uv run sheets.py --dry-run` finds every sheet current. The sheets measure 116,718–123,916 bytes, not the 118–124 KB the addendum above gives. The upload also showed that the R2 API can fail a single put with a transient `500` (code 10500), so every put is now tried again after 5 and 20 seconds before a run stops (`scripts/images/r2.py`, issue #70). Source: `docs/plans/EXECPLAN_SKILLCARD_DATA_AND_ICONS.md` Progress 2026-10-31 17:21Z and 17:45Z, decision K20.
